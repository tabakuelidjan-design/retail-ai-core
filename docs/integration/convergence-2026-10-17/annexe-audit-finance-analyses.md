# Notes d'audit — Finance / Analytics / Growth (agent lecture seule, core-p0 ebff21e ; rien exécuté)
- Finance : 66 fichiers src/finance + serveur de 1445 lignes (~123 routes) : factures/devis/avoirs (moteur déterministe, TVA, numérotation, PDF, UBL), paiements/allocations, créances/dettes, boîte d'achats (PDF texte local sans IA, UBL, notes de frais), import CSV bancaire + rapprochement, trésorerie, préparation Peppol belge, pack comptable, synchro stock vers Shopify, contacts (CBEAPI, VIES, annuaire Peppol). ~75 fichiers de test « finance ».
- Seulement contrats/faux : **aucun point d'accès Peppol réel** (NoPeppolProvider / fake), **aucun adaptateur bancaire PSD2** (NoBankAdapter / fake ; bank.js interdit les noms d'initiation de paiement), aucun mailer réel (NoMailAdapter), **aucun fournisseur IA enregistré**. Finance ne peut pas encore remplir l'obligation Peppol : ne pas la présenter comme conforme.
- Serveurs : chaque service = processus + déploiement Railway séparés (NORDLA_SERVICE) ; rien de monté dans un serveur unifié ; Growth (src/growth/server/serve.js) hors service-start, local 127.0.0.1:4413, **sans authentification**. Variables Finance : FINANCE_HOSTED|RAILWAY_*, PORT, FINANCE_ALLOWED_HOSTS, FINANCE_DASHBOARD_TOKEN (≥24), NORDLA_MERCHANT_ID, SUPABASE_*, CBEAPI_KEY, clé de coffre bancaire. Analytics : ANALYTICS_HOSTED, ANALYTICS_ALLOWED_HOSTS, ANALYTICS_ACCESS_TOKEN (≥24), NORDLA_ASSISTANT_PROVIDER…
- Auth : Finance = un jeton statique partagé (comparaison à temps constant, 5 échecs/IP → 5 min, cookie HttpOnly SameSite=Strict Secure, 8 h, CSRF + Origin sur les mutations, sessions hachées en fichier) ; Analytics = HTTP Basic (mot de passe = jeton, nom ignoré), pas de session/CSRF (Origin sur /api/ask), **aucune auth hors mode hébergé** ; **ni l'un ni l'autre n'utilise l'identité Core** (seul Sourcing). Faiblesses : pas d'identité par personne ni de rôles ; acteur d'audit Finance codé en dur {type:'merchant', id:'dashboard'} (app.js ~60) ; limite de débit en mémoire ; réglages/audit/sessions Finance = fichiers locaux data/local/finance non durables ni indexés par marchand ; écriture d'audit qui avale les erreurs.
- Données : toutes les tables fin_* ont merchant_id NOT NULL ; fin_events et fin_payments append-only par triggers ; fin_artifacts immuable ; **RLS activée sans aucune politique CREATE POLICY ; serveur = clé service role (contourne RLS) ⇒ isolation purement applicative** (77 filtres merchant_id dans supabase-store.js) ; pièces jointes Finance dans Supabase Storage (politiques de seau non vérifiées) ; Analytics lit reports/*.json estampillés du marchand (fichier étranger/non estampillé non servi).
- IA : aucun fournisseur fourni (PROVIDER_REGISTRY vide ; aiProvider jamais passé hors tests) ⇒ « Ask » = chemin déterministe, rien ne sort ; si un adaptateur est ajouté : chemin hérité envoie {intent, période, chiffres, devise}, orchestrateur : outils agrégés/pseudonymisés, MAX_TOOL_CALLS=4, timeout 20 s, historique 6×300 caractères ; **pas de consentement par marchand ni de porte contractuelle dans le code**. Finance : zéro LLM (PDF local ; images = saisie manuelle).
- Approbation : **pas de vrai maker/checker** : « approuver » = actor.type==='merchant' (service.js:103,125) et le tableau de bord agit toujours en marchand ⇒ la même personne crée/approuve/émet/envoie ; CLI exige FINANCE_ACTOR=merchant:<nom> ; agent ne peut pas approuver. **Non gardés au-delà de session+CSRF** : paiements (enregistrer/annuler/allouer/rembourser), rapprochement bancaire, connexion/déconnexion bancaire, réglages + profil vendeur (IBAN, TVA), **application du stock vers Shopify (écriture Shopify, app.js:1295)**, archives/contacts. /api/peppol/webhook public (auth par provider.verifyWebhook ; le faux compare un en-tête en clair = test seulement : vérifier qu'il n'est jamais utilisé en prod).
- UI : Finance FR/NL/EN responsive ; Analytics (Brief, Ce qui a changé, Explorateur, Clients, Produits, Ask + dictée navigateur) ; Growth UI (captures 375/1440) ; pas d'application mobile séparée.
- Démo : src/finance/server/demo.js = démo synthétique locale (port 4311, jeton constant demo-token…), non lancée par service-start ; ne jamais la déployer.
- Intégration avec Core : aucun serveur ni navigation partagés ; mêmes base Supabase, NORDLA_MERCHANT_ID, assets partagés, table sync_runs ; Analytics settingsHref:null ; aucun lien croisé Core/Finance/Analytics.
